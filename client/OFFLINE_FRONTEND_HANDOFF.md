# Frontend Offline and Device QA

## Implemented

- Production Workbox precache generated by the already-installed Vite PWA plugin.
  The manifest includes the actual versioned JS/CSS, app HTML and local branding.
  It does not cache API responses, authenticated HTML responses, or QA fixtures.
  API/QA navigation is excluded from the app-shell fallback. Unknown asset requests
  are not answered with HTML. New releases wait for open windows to close, avoiding
  forced reload/data loss during an assessment.
- Replaced the empty favicon reference with a real vector app icon. Physical-device
  installation compatibility is not certified; platform-specific raster icons may
  still be required for the agreed target tablet/browser.
- Workers with a valid existing session can restore their own saved assignments
  when offline or on a network-only API failure. Device copies are explicitly labeled
  stale/unverified against the server. A successful empty response clears stale tasks.
  HTTP 401, 403 and server errors are never converted into cached success.
- Saved reports load independently of the assignment request. IndexedDB preserves
  reports/evidence per owner; resaving the same task replaces the existing entry
  rather than duplicating the in-memory list. Cache refresh does not delete drafts.
- Photo input accepts JPEG/PNG/WebP up to 10 MB, checks file signatures and browser
  decoding, hashes the original bytes and records capture time separately from save
  time. Invalid retakes cannot reuse old photo/hash/GPS completion state.
- GPS errors distinguish permission denial, timeout, unavailable/unsupported devices,
  and invalid coordinates. Actual device accuracy is retained, not simulated.
- Submission remains disabled. No upload, sync, dispatch, appeal, database or backend
  implementation was added by this work.

## How to test offline startup

1. Build and serve the production output (`npm run preview -- --host 127.0.0.1
   --port 4173 --strictPort`). Development Vite does not install a service worker.
2. Open once online to install/cache the shell, then reload. Future offline visits
   require those cached files; a device that has never visited cannot install offline.
3. Test the browser's real network-offline mode or stop only the preview process and
   reload. Port 4173 is a separate origin/storage area from development port 3000.
4. For authenticated field tests, use the agreed CORS origin and existing real login;
   do not invent a token or allow mock fallback. Download assignments before disconnecting.
5. Close the temporary preview when done. Keep normal frontend development on port 3000.

## Security and remaining dependencies

- Session storage and token expiry are unchanged. Offline access requires the same
  browser session and a still-valid token; after expiry or a new session, reconnect
  and authenticate. Saved reports are retained, but access is not granted by knowing
  an owner ID. A longer offline authorization window requires Renz/Mae approval and
  a documented design, not a frontend expiry bypass.
- The current form saves completed reports explicitly. Unsaved/incomplete form edits
  are not auto-saved. Local storage can be cleared/evicted by the browser; it is not a
  server backup or proof of encrypted storage on shared devices.
- Still pending: physical-tablet GPS/camera permission and accuracy testing, install
  behavior, full browser-restart offline testing, and two-report airplane-mode sync.
- Mae confirmed that submission payloads are examples, not a mounted endpoint;
  sample URLs/hashes are not real uploads. Wait for upload/storage, evidence validation,
  replay rules and atomic submission/audit persistence before enabling sync.
- Appeals still need an approved API contract/endpoint and fixtures from Renz/Charles.
- Audit success needs actual entries/range in this DB. Do not reuse another test DB's
  1..3 range, reset/reseed existing data, or fabricate audit history.
